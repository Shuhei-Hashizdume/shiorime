## 1. 本棚（トップ）

見本：[mockups/shelf.html](mockups/shelf.html)

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 「本棚」。右側に、選んでいる切り替えの冊数（例：「7冊」） |
| 切り替え | 「読書中」「読了」「すべて」の順。初めは「読書中」を選んだ状態 |
| 本の一覧 | 表紙を3列で並べる。表紙の下にタイトル（2行まで、それ以上は「…」で省略）と読書ステータス（「読書中」または「✓読了」） |
| 本を追加 | 右下に「＋本を追加」のボタン。共通メニューの上に置く |
| 共通メニュー | 本棚（選択中）・気づき・プロフィール |

- 冊数は、選んでいる切り替えの冊数を表示する。理由：見出しの冊数と並んでいる冊数がずれると、混乱するため。
- 切り替えの順番を「読書中・読了・すべて」とし、初めは「読書中」にする。理由：利用者は、今読んでいる本に気づきを書くことが最も多いため。
- 切り替えの選択中は、枠線と薄い灯りの色で表す（visual.md「3. 色」のとおり）。塗りつぶしは「本を追加」だけにする。
- 表紙がない本・手入力の本は、アプリのアイコン画像で表示する（要件定義書 5.2 のとおり）。
- 一覧の最後の行が「本を追加」に隠れないよう、一覧の下にボタンの高さ分の余白をあける。

### 並び順と読み込み

- 並び順：登録した日時が新しい順（固定）。理由：利用者が予想しやすいため。並び順を選べる機能は MVP では作らない。
- 30冊ずつ読み込み、一覧の下までスクロールしたら次の30冊を自動で読み込む。理由：本が数百冊になっても、最初の表示が遅くならないようにするため。
- 次の30冊の読み込みに失敗した場合は、一覧の下に「読み込めませんでした」と「もう一度読み込む」ボタンを表示する。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 表紙またはタイトルを押す | 本の詳細へ |
| 切り替えを押す | その読書ステータスの本だけを表示（「すべて」は全部） |
| 「＋本を追加」を押す | 本の検索・登録へ |
| 共通メニュー | 各画面へ |

- 本の編集・削除は本棚では行わず、本の詳細の「⋮」メニューから行う。理由：表紙を並べた画面には操作を置く場所がなく、誤って削除するのも防げるため。
- 選んだ切り替えは URL に入れる（例：`/shelf?status=finished`）。
  - 本の詳細から戻るボタンで戻ったときは、選んでいた切り替えのまま戻る。
  - アプリを開き直したときと、共通メニューの「本棚」を押したときは「読書中」から始まる。
  - 理由：ブラウザの戻る操作で自然に元の状態に戻せ、状態を保存する仕組みを別に作らずに済むため。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 表紙と同じ形のスケルトン（3列×3行） |
| 通常 | 本の一覧 |
| 本がまだない | アイコン、「最初の1冊を、本棚に。」、「いま読んでいる本や、気になっている本を追加しましょう。」、「本を追加する」ボタン。切り替えと右下のボタンは出さない |
| 選んだ切り替えの本がない（本はある） | 「読書中の本はありません」（読了・すべての場合はそれぞれの名前）、「読み終えた本は「読了」で見られます。」（読書中のときだけ）、「本を追加する」ボタン。右下のボタンは出さない |
| 読み込みの失敗 | 「本棚を読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

- 「本がまだない」と「選んだ切り替えの本がない」は、別の表示にする。理由：本が1冊もない人には登録を勧め、読書中の本がないだけの人には、本がどこにあるかを伝えるため。

### 関連する決まり（ほかの画面に関わるもの）

- 本を「読了」に変えたときのトーストは「読了にしました（本棚の「読了」に移りました）」とする。理由：本棚を「読書中」から開くため、読了にした本が見えなくなり、消えたと思われるのを防ぐため。
- 登録時に「読了」を選んだ本も、登録後は本の詳細に移るため、同じ理由で、本の詳細に読書ステータスを表示しておく。

### API（api.md で詳しく決める）

- 本の一覧の取得：読書ステータスでの絞り込み（読書中／読了／指定なし）と、30冊ずつの読み込み（続きの位置を渡す方式）に対応する。
- 冊数は、絞り込みの条件ごとに返す。
- 自分の本だけを返す。ほかの利用者の本は、条件を変えても返さない（全画面の API で共通の決まり）。
