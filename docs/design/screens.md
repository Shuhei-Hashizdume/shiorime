## 1. 本棚（トップ）

見本：[mockups/shelf.html](mockups/shelf.html)

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 「本棚」。右側に、選んでいる切り替えの冊数（例：「7冊」） |
| 切り替え | 「読書中」「読了」「すべて」の順。初めは「読書中」を選んだ状態 |
| 本の一覧 | 表紙を3列で並べる。表紙の下にタイトル（2行まで、それ以上は「…」で省略）と読書ステータス（「読書中」または「✓読了」） |
| 本を追加 | 右下に「＋本を追加」のボタン。共通メニューの上に置く |
| 共通メニュー | 本棚（選択中）・気づき・プロフィール |

- 冊数は、選んでいる切り替えの冊数を表示する。理由：見出しの冊数と並んでいる冊数がずれると、混乱するため。
- 切り替えの順番を「読書中・読了・すべて」とし、初めは「読書中」にする。理由：利用者は、今読んでいる本に気づきを書くことが最も多いため。
- 切り替えの選択中は、枠線と薄い灯りの色で表す（visual.md「3. 色」のとおり）。塗りつぶしは「本を追加」だけにする。
- 表紙がない本・手入力の本は、アプリのアイコン画像で表示する（要件定義書 5.2 のとおり）。
- 一覧の最後の行が「本を追加」に隠れないよう、一覧の下にボタンの高さ分の余白をあける。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 表紙 | データベース（本の表紙の URL）。ない場合はアイコン画像 |
| タイトル | データベース |
| 読書ステータス | データベース |
| 冊数 | データベース（選んでいる切り替えの条件で数える） |

### 並び順と読み込み

- 並び順：登録した日時が新しい順（固定）。理由：利用者が予想しやすいため。並び順を選べる機能は MVP では作らない。
- 30冊ずつ読み込み、一覧の下までスクロールしたら次の30冊を自動で読み込む。理由：本が数百冊になっても、最初の表示が遅くならないようにするため。
- 次の30冊の読み込みに失敗した場合は、一覧の下に「読み込めませんでした」と「もう一度読み込む」ボタンを表示する。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 表紙またはタイトルを押す | 本の詳細へ |
| 切り替えを押す | その読書ステータスの本だけを表示（「すべて」は全部） |
| 「＋本を追加」を押す | 本の検索・登録へ |
| 共通メニュー | 各画面へ |

- 本の編集・削除は本棚では行わず、本の詳細の「⋮」メニューから行う。理由：表紙を並べた画面には操作を置く場所がなく、誤って削除するのも防げるため。
- 選んだ切り替えは URL に入れる（例：`/shelf?status=finished`）。
  - 本の詳細から戻るボタンで戻ったときは、選んでいた切り替えのまま戻る。
  - アプリを開き直したときと、共通メニューの「本棚」を押したときは「読書中」から始まる。
  - 理由：ブラウザの戻る操作で自然に元の状態に戻せ、状態を保存する仕組みを別に作らずに済むため。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 表紙と同じ形のスケルトン（3列×3行） |
| 通常 | 本の一覧 |
| 本がまだない | アイコン、「最初の1冊を、本棚に。」、「いま読んでいる本や、気になっている本を追加しましょう。」、「本を追加する」ボタン。切り替えと右下のボタンは出さない |
| 選んだ切り替えの本がない（本はある） | 「読書中の本はありません」（読了・すべての場合はそれぞれの名前）、「読み終えた本は「読了」で見られます。」（読書中のときだけ）、「本を追加する」ボタン。右下のボタンは出さない |
| 読み込みの失敗 | 「本棚を読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

- 「本がまだない」と「選んだ切り替えの本がない」は、別の表示にする。理由：本が1冊もない人には登録を勧め、読書中の本がないだけの人には、本がどこにあるかを伝えるため。

### 関連する決まり（ほかの画面に関わるもの）

- 本を「読了」に変えたときのトーストは「読了にしました（本棚の「読了」に移りました）」とする。理由：本棚を「読書中」から開くため、読了にした本が見えなくなり、消えたと思われるのを防ぐため。
- 登録時に「読了」を選んだ本も、登録後は本の詳細に移るため、同じ理由で、本の詳細に読書ステータスを表示しておく。

### API（api.md で詳しく決める）

- 本の一覧の取得：読書ステータスでの絞り込み（読書中／読了／指定なし）と、30冊ずつの読み込み（続きの位置を渡す方式）に対応する。
- 冊数は、絞り込みの条件ごとに返す。
- 自分の本だけを返す。ほかの利用者の本は、条件を変えても返さない（全画面の API で共通の決まり）。

## 2. 本の検索・登録

見本：[mockups/search.html](mockups/search.html)

本棚の「本を追加」から開く。Google Books で検索して選ぶか、見つからない場合は手入力で追加する。

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 左に戻るボタン、「本を追加」 |
| 検索欄 | 「タイトル・著者名で検索」。入力があるときは右に消すボタン。画面を開くと自動でカーソルが入る |
| 検索結果 | 1行に1冊。表紙・タイトル・著者・出版年。本棚にある本には「✓本棚にあります」 |
| 手入力の案内 | 「手入力で追加する」と、その下に「※検索で見つからない本は、タイトルと著者を入力して追加できます。」 |
| 共通メニュー | 本棚（選択中）・気づき・プロフィール |

- 手入力の案内は、検索前・検索結果の一番下・見つからないときの3か所に置く。理由：手入力がどういうときに使うものかを、初めての人にもわかるようにするため。
- 「本棚にあります」は、枠線と薄い灯りの色で表す（押すボタンと見分けるため。visual.md「3. 色」のとおり）。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 表紙 | Google Books（サーバーで https に直して渡す）。ない場合はアイコン画像 |
| タイトル | Google Books |
| 著者 | Google Books（複数いる場合は「、」でつなぐ）。ない場合は表示しない |
| 出版年 | Google Books の出版日の年の部分。ない場合は表示しない。**表示するだけで、本棚に追加するときは保存しない** |
| 本棚にあるか | サーバーで、Google Books の識別子と自分の本棚の本を照らし合わせて判定する |

- 出版年を保存しない理由：役に立つのは、同じ本の複数の版から1つを選ぶ検索のときだけであり、データベースと要件（本の情報はタイトル・著者・ISBN・表紙）を変えずに済むため。保存が必要になれば後から追加できる。

### 検索

- キーボードの「検索」か Enter を押したときだけ検索する。入力のたびには検索しない。理由：日本語は変換の途中でも文字が変わり、無駄な検索が増えるため。Google Books の利用回数の上限を守るため。
- 前後の空白を除いて空の場合は、検索しない。
- 画面から Google Books を直接呼ばず、自分のサーバーを通す。理由：API キーを画面側のコードに置かないため。表紙の URL を https に直す処理と、検索の回数制限をサーバーの1か所にまとめるため。
- 検索の回数制限：1人あたり1分に10回まで。理由：普通に使えば届かない回数にし、自動で大量に検索されて Google Books の利用枠を使い切られるのを防ぐため。
- 結果は20件ずつ表示し、一番下に「もっと見る」ボタンを置く。理由：目当ての本は上のほうにあることがほとんどで、自動で読み込み続けると無駄な検索が増えるため。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 戻るボタン | 本棚へ（本棚で選んでいた切り替えのまま） |
| 検索結果の本を押す | 「本棚に追加」のシートを開く |
| 「本棚にあります」の本を押す | その本の詳細へ |
| 「手入力で追加する」 | 「手入力で追加」のシートを開く |
| シートの「本棚に追加する」 | 本を追加して本の詳細へ移り、トースト「本棚に追加しました」 |
| シートの「キャンセル」・シートの外を押す・下にスワイプ・Esc キー | シートを閉じる（何も追加しない） |

### シート

**本棚に追加（検索結果から）**
- 選んだ本の表紙・タイトル・著者・出版年
- 読書ステータス：「読書中」「読了」（初めは「読書中」）
- 「本棚に追加する」「キャンセル」
- 理由：押し間違えてもすぐには追加されず、版の確認と読書ステータスの選択を1か所でできるため。

**手入力で追加**
- タイトル（必須）：検索した言葉を最初から入れておく
- 著者（任意）
- 読書ステータス：「読書中」「読了」（初めは「読書中」）
- 「本棚に追加する」「キャンセル」
- 表紙はアプリのアイコン画像を使う（要件定義書 5.2 のとおり）。
- タイトルが空のまま「本棚に追加する」を押した場合は、タイトル欄の下に「タイトルを入力してください」と表示する。
- タイトルは200文字まで、著者は100文字まで（要件定義書 6章「入力の上限」のとおり）。超えた場合は、欄の下に「タイトルは200文字以内で入力してください」（著者も同様）と表示する。

### 状態

| 状態 | 表示 |
| --- | --- |
| 開いたとき（検索前） | 「本のタイトルや著者名を入れて、キーボードの「検索」を押してください。」と手入力の案内 |
| 検索中 | 結果と同じ形のスケルトン |
| 検索結果 | 結果の一覧、一番下に「もっと見る」（続きがある場合）と手入力の案内 |
| 見つからない | 「見つかりませんでした」「言葉を短くしたり、著者名で探したりすると見つかることがあります。」、「手入力で追加する」ボタンと説明 |
| 検索の失敗（Google Books の障害など） | 「本を検索できませんでした。時間をおいてもう一度お試しください。」と手入力の案内 |
| 検索の回数制限に達した | 「検索の回数が多すぎます。1分ほど待ってから、もう一度お試しください。」 |
| 追加の失敗 | シートの中に「本棚に追加できませんでした。もう一度お試しください。」（シートは閉じない） |
| 追加しようとした本が既に本棚にある | シートを閉じて、その本の詳細へ移り、「この本は既に本棚にあります」と表示する（要件定義書 5.2 のとおり。別の端末から追加していた場合などに起きる） |

### API（api.md で詳しく決める）

- 本の検索：検索の言葉と、何件目からかを受け取り、20件と「続きがあるか」を返す。各結果に「本棚にあるか」と、本棚にある場合はその本の ID を含める。回数制限：1人1分10回。
- 本の追加（検索結果から）：Google Books の識別子と読書ステータスを受け取る。タイトル・著者・表紙・ISBN は、改ざんを防ぐため、サーバーが Google Books から取り直して保存する。
- 本の追加（手入力）：タイトル・著者・読書ステータスを受け取る。

## 3. 本の詳細

見本：[mockups/book.html](mockups/book.html)

本棚にある1冊の本の画面。読書ステータスの変更、気づきを書く・見る、本の編集・削除を行う。本棚から削除した本の詳細は開けない（削除した本の気づきは、気づき一覧から見る）。

### 入り口

| どこから | どうすると |
| --- | --- |
| 本棚 | 表紙かタイトルを押す |
| 本の検索（まだ本棚にない本） | 確認シートの「本棚に追加する」を押す |
| 本の検索（すでに本棚にある本） | 結果の本を押す（確認シートは出ない） |
| 手入力で追加 | シートの「本棚に追加する」を押す |

- 確認シートの表紙・タイトルは、押しても何も起きない。理由：本の詳細は本棚にある本の画面であり、まだ追加していない本には詳細の画面がないため。

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 左に戻るボタン、右に「⋮」 |
| 本の情報 | 表紙・タイトル・著者（著者がない本は、著者の行を出さない） |
| 読書ステータス | 「読書中」「✓読了」の切り替え。押すとすぐ保存する |
| この本の気づき | 件数と「この本の気づきを見る ＞」。0件のときは「心に残った一文や、読んで考えたことを書き留めてみましょう。」 |
| 気づきを書く | 「＋気づきを書く」（灯りの色で塗りつぶす） |
| 共通メニュー | 本棚（選択中）・気づき・プロフィール |

- 本の気づきを並べて表示するのは「本ごとの気づき一覧」だけとし、この画面には件数と移動のボタンだけを置く（要件定義書 5.4 のとおり）。
- ISBN と登録日は表示しない。理由：利用者が見ても役に立たないため。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 表紙・タイトル・著者 | データベース（本） |
| 読書ステータス | データベース（本） |
| 気づきの件数 | データベース（この本の気づきを数える） |
| 編集できるか | データベース（Google Books の識別子がない本＝手入力の本だけ編集できる） |

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 戻るボタン | 前の画面へ。ただし本を追加した直後は本棚へ（下の補足） |
| 読書ステータスを押す | すぐ保存し、トーストを出す（下の表） |
| 「この本の気づきを見る」 | 本ごとの気づき一覧へ |
| 「＋気づきを書く」 | 気づきの作成へ（本は選択済み） |
| 「⋮」 | メニューのシートを開く |

- 本を追加した直後の戻るボタン：検索画面ではなく本棚に戻る。実装では、追加後に本の詳細へ移るとき、ブラウザの履歴の検索画面を本の詳細で置き換える。理由：追加し終えたあとに検索結果へ戻っても、することがないため。

### 読書ステータスの変更

| 変更 | トースト |
| --- | --- |
| 読書中 → 読了 | 「読了にしました（本棚の「読了」に移りました）」 |
| 読了 → 読書中 | 「読書中にしました」 |

- 確認は出さない。理由：すぐ元に戻せる操作のため。
- 保存に失敗した場合は、切り替えを元に戻し、「読書ステータスを変更できませんでした。もう一度お試しください。」と表示する。理由：画面の表示と保存されている内容がずれないようにするため。

### 「⋮」メニュー

| 本の種類 | メニュー |
| --- | --- |
| Google Books から追加した本 | 「本棚から削除」だけ |
| 手入力で追加した本 | 「本の情報を編集」「本棚から削除」 |

- 「本棚から削除」は夕焼けの色にする。メニューの一番下に「キャンセル」。
- Google Books から追加した本は編集できない（要件定義書 5.2 のとおり）。画面で出さないだけでなく、サーバーでも受け付けない。

### シート

**本の情報を編集（手入力の本だけ）**
- タイトル（必須）・著者（任意）。今の値を最初から入れておく。
- 「保存する」「キャンセル」。保存したらトースト「本の情報を変更しました」。
- タイトルが空の場合は、タイトル欄の下に「タイトルを入力してください」。タイトルは200文字まで、著者は100文字まで（要件定義書 6章のとおり）。
- 保存に失敗した場合は、シートの中に「保存できませんでした。もう一度お試しください。」（シートは閉じない）。

**削除の確認**
- 「この本を本棚から削除しますか？」「この本の気づきは、気づき一覧に残ります。」（要件定義書 5.2 のとおり）
- 「削除する」（夕焼けの色）「キャンセル」。
- 削除したら本棚へ戻り、トースト「本棚から削除しました」。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 表紙・タイトル・切り替えの形のスケルトン |
| 通常 | 上の配置のとおり |
| 追加した直後 | 通常の表示に、トースト「本棚に追加しました」。トーストを出している間は、その分だけ画面の下に余白をとり、「＋気づきを書く」が隠れないようにする |
| 既に本棚にある本を追加しようとした | 画面の上に「この本は既に本棚にあります」（枠線と薄い灯りの色）。トーストは成功の知らせだけに使う決まりのため使わない |
| 本が見つからない（削除済み・他人の本・存在しない ID） | 「この本は見つかりませんでした」と「本棚へ戻る」ボタン。他人の本も同じ表示にする（他人の本があるかどうかを知らせないため） |
| 読み込みの失敗 | 「本を読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

### API（api.md で詳しく決める）

- 本の取得：本の情報・読書ステータス・気づきの件数・編集できるかを返す。自分の本でなければ「見つからない」として返す。
- 読書ステータスの変更、本の情報の編集（手入力の本だけ。Google Books の本は拒否する）、本の削除。

## 4. 気づき一覧

見本：[mockups/notes.html](mockups/notes.html)

共通メニューの「気づき」から開く。本棚にある本を、気づきが0件の本も含めて1つの一覧で並べる。どの本を押しても「本ごとの気づき一覧」に移り、そこから気づきを書ける（要件定義書 5.4 のとおり）。

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 「気づき一覧」。右に気づきの総数（例：「気づき 16件」） |
| 並び順 | 左に「並び順：最近書いた順」、右に並び替えのアイコン（上下の矢印。文字は付けない） |
| 本の一覧 | 1冊ずつカード。表紙・タイトル・「気づき ◯件」・「最後に書いた日：10月20日」（今日は「今日」。0件の本は出さない）。削除済みの本には「本棚から削除済み」 |
| 共通メニュー | 本棚・気づき（選択中）・プロフィール |

- 見出しを「気づき」ではなく「気づき一覧」にする。理由：本ごとの一覧や気づきの詳細ではなく、全体の一覧であることがわかるようにするため。共通メニューの文字は、幅が限られるため「気づき」のままとする。
- 見出しの右には冊数を出さない。理由：本棚の冊数と同じ数字になり、意味が重なるため。
- 段（気づきのある本／ない本）には分けない。0件の本を探すときは、並び替えの「気づきが少ない順」を使う。
- 削除済みの本は、表紙を少し薄くし、灰色の枠で「本棚から削除済み」と表示する。灯りの色は使わない（注意を引く必要がないため）。
- この画面には「気づきを書く」ボタンを置かない。理由：気づきは必ず本を選んで書くため。本を押した先の画面から書く。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 表紙・タイトル | 本棚にある本はデータベース（本）。削除済みの本は、気づきに記録した本の情報（要件定義書 5.3 のとおり） |
| 気づきの件数 | データベース（本ごとに数える） |
| 最後に書いた日 | データベース（本ごとに、気づきの作成日時の最も新しいもの） |
| 本棚から削除済みか | データベース |
| 気づきの総数 | データベース（自分の気づきを数える） |

### 並び替え

| 並び順 | 並べ方 | 同じ件数・0件どうしのとき |
| --- | --- | --- |
| 最近書いた順（初め） | 最後に気づきを書いた日時が新しい本から。0件の本は最後 | 本棚に登録した日時が新しい本から |
| 気づきが多い順 | 気づきの件数が多い本から | 最後に書いた日時が新しい本から |
| 気づきが少ない順 | 気づきの件数が少ない本（0件）から | 本棚に登録した日時が新しい本から |

- 並び替えのアイコンは、文字を付けずアイコンだけにする。理由：上下の矢印で意味が伝わり、左に今の並び順を表示しているため。押せる範囲は44px四方とし、画面読み上げ用に「並び替え」という名前を付ける（aria-label）。
- 並び替えのアイコンを押すと、下からシートを開く。3つの並び順と、それぞれの説明（例：「まだ気づきのない本から」）を並べ、今の並び順に印を付ける。選ぶとシートを閉じ、すぐ並び替える。「キャンセル」で何も変えずに閉じる。
- 並び替えはサーバー（データベース）で行う。理由：30冊ずつ読み込むため、画面側で並び替えると、まだ読み込んでいない本が順番に入らないため。
- 選んだ並び順は URL に入れる（例：`/notes?sort=few`）。本ごとの気づき一覧から戻ったときは同じ並び順のまま戻り、共通メニューから開き直したときは「最近書いた順」に戻る（本棚の切り替えと同じ考え方）。
- 読み込みは30冊ずつ、下までスクロールしたら次を読み込む（本棚と同じ）。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 本を押す（0件の本も含む） | その本の「本ごとの気づき一覧」へ |
| 並び替えのアイコン | 並び替えのシートを開く |
| 共通メニュー | 各画面へ |

- 0件の本を押した場合も、気づきの作成に直接は移らず「本ごとの気づき一覧」へ移る。移った先には「まだ気づきがありません」と「＋気づきを書く」を出す。理由：どの本を押しても行き先が同じ方が迷わないため。気づきタブ → 本 → 気づきを書く、の3回で書け、本棚から書く場合と同じ回数になる。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | カードと同じ形のスケルトン |
| 通常 | 本の一覧 |
| 本はあるが、気づきがまだない | すべての本が「気づき 0件」で並ぶ（特別な表示はしない） |
| 本棚に本が1冊もなく、削除済みの本の気づきもない | アイコン、「まだ本がありません」、「本棚に本を追加すると、ここから気づきを書けるようになります。」、「本を追加する」ボタン（本の検索・登録へ） |
| 読み込みの失敗 | 「気づき一覧を読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

### API（api.md で詳しく決める）

- 気づき一覧の取得：並び順（最近書いた順・多い順・少ない順）と、30冊ずつの読み込みに対応する。本ごとに、表紙・タイトル・気づきの件数・最後に書いた日時・削除済みかを返す。気づきの総数も返す。
- 本棚にある本と、削除済みの本（気づきに記録した本の情報でまとめる）を1つの一覧として返す。自分のものだけを返す。

## 5. 本ごとの気づき一覧

見本：[mockups/booknotes.html](mockups/booknotes.html)

1冊の本の気づきを並べる画面。気づきを押すと「気づきの詳細」に移る。

### 入り口

| どこから | どうすると |
| --- | --- |
| 気づき一覧 | 本を押す（0件の本も含む） |
| 本の詳細 | 「この本の気づきを見る」を押す |

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 左に戻るボタン |
| 本の情報 | 表紙・タイトル・著者・「気づき ◯件」。削除済みの本は「本棚から削除済み」 |
| 気づきの一覧 | 1件ずつカード（下の表） |
| 気づきを書く | 右下に「＋気づきを書く」（本棚の「本を追加」と同じ形） |
| 共通メニュー | 本棚・気づき（選択中）・プロフィール |

**気づきのカード**

| 項目 | 表示 |
| --- | --- |
| ページ | 「P.142」。ないときは「ページなし」 |
| 書いた日 | 「10月18日」（今日は「今日」） |
| 引用 | 紙片で表す（visual.md「6. 栞と引用の表現」のとおり）。2行まで、はみ出す分は「…」。ないときは出さない |
| 本文 | 3行まで、はみ出す分は「…」 |
| 次の一歩の数 | その気づきの最新のAI提案の次の一歩の数（1〜3個）を、芽のアイコンと「次の一歩 2件」で表示。AI提案がないときは出さない |

- 引用・本文を省略する理由：本文は最大1000字あり、全文を出すと1件で画面が埋まるため。続きは気づきの詳細で読む。
- 次の一歩の数は、完了したAI提案のものだけを数える（要件定義書 5.5 のとおり。AI提案は1つの気づきに1つだけ）。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 表紙・タイトル・著者 | 本棚にある本はデータベース（本）。削除済みの本は、気づきに記録した本の情報 |
| 本棚から削除済みか | データベース |
| 気づきの件数 | データベース（この本の気づきを数える） |
| ページ・書いた日・引用・本文 | データベース（気づき） |
| 次の一歩の数 | データベース（その気づきの最新の完了したAI提案の次の一歩を数える） |

### 並び順と読み込み

- 書いた日時が新しい順（固定）。並び替えは作らない。
- 20件ずつ読み込み、下までスクロールしたら次を読み込む。理由：気づきのカードは本より縦に長いため、本棚の30冊より少なくする。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 戻るボタン | 前の画面へ（気づき一覧なら、選んでいた並び順のまま） |
| 気づきを押す | 気づきの詳細へ |
| 「＋気づきを書く」 | 気づきの作成へ（この本を選んだ状態） |

- 気づきの編集・削除は、この画面では行わず、気づきの詳細の「⋮」から行う（アプリ全体で統一）。

### 本棚から削除した本の場合

- 本の情報の下に「本棚から削除済み」と表示する。
- 一覧の上に「この本は本棚から削除されているため、新しい気づきは書けません。」と表示し、「＋気づきを書く」は出さない。理由：気づきは本棚にある本に書く決まりのため（要件定義書 5.3）。
- 今ある気づきは、これまでどおり見る・編集する・削除する・AI提案を受けることができる。
- サーバーでも、削除済みの本への新しい気づきは受け付けない。
- 同じ本を本棚に登録し直しても、気づきは自動で付け直さない（要件定義書 5.4 のとおり。付け直す機能は MVP では作らない）。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 本の情報と、カードの形のスケルトン |
| 通常 | 上の配置のとおり |
| 気づきがまだない（本棚にある本） | 「まだ気づきがありません」「心に残った一文や、読んで考えたことを書き留めてみましょう。」と、真ん中に「＋気づきを書く」。右下のボタンは出さない（同じボタンを2つ出さないため） |
| 本が見つからない（他人の本・存在しない ID） | 「この本は見つかりませんでした」と「気づき一覧へ戻る」ボタン（他人の本も同じ表示） |
| 読み込みの失敗 | 「気づきを読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

### API（api.md で詳しく決める）

- 本ごとの気づきの取得：本の情報（削除済みかを含む）と、気づき（ページ・書いた日時・引用・本文・次の一歩の数）を20件ずつ、新しい順で返す。自分のものだけを返す。
- 一覧では引用・本文を省略して表示するが、API は全文を返し、画面側で行数を切る（省略の位置は端末の幅で変わるため）。

## 6. 気づきの詳細

見本：[mockups/notedetail.html](mockups/notedetail.html)

1件の気づきの全文と、その気づきの次の一歩（最新のAI提案）を表示する画面。AI提案はここから始める。

### 入り口

| どこから | どうすると |
| --- | --- |
| 本ごとの気づき一覧 | 気づきを押す |
| 気づきの作成 | 保存すると、この画面に移る（トースト「気づきを保存しました」） |
| AI提案 | 完了後の「気づきに戻る」 |

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 左に戻るボタン、右に「⋮」 |
| 本の情報 | 小さな表紙・タイトル・「P.142　10月18日に書いた気づき」（ページがないときは日付だけ） |
| 気づき | カード（右上に栞）。引用の紙片（ないときは出さない）と本文の全文 |
| 次の一歩 | 「10月20日のAI提案」、次の一歩の番号付き一覧（1〜3個）、「深掘りと回答も見る ＞」 |
| AI提案のボタン | 次の一歩がないとき：「AI提案を受ける」（塗りつぶし）と説明文。あるとき：「もう一度AI提案を受ける」（枠線） |
| 残り回数 | 「本日あと3回（気づきの登録は何件でもできます）」 |
| 共通メニュー | 本棚・気づき（選択中）・プロフィール |

- 栞は、この画面の気づきのカードにだけ付ける（visual.md「6. 栞」のとおり）。
- 次の一歩は、最新の完了したAI提案1つだけを表示する（要件定義書 5.5「保存するAI提案の数」）。
- 「もう一度AI提案を受ける」を枠線にする理由：次の一歩があるときの主な使い方は、読んで行動することであり、もう一度受けるのは結果が合わなかったときに限られるため。
- 次の一歩がないときの説明文：「AIが気づきを深掘りする質問をし、あなたの回答から次の一歩を一緒に考えます。」
- 「（気づきの登録は何件でもできます）」は、残り回数と一緒に必ず表示する。理由：AI提案の回数制限を、気づきの登録の制限と誤解されないようにするため。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| 本の情報 | 本棚にある本はデータベース（本）。削除済みの本は、気づきに記録した本の情報 |
| ページ・書いた日・引用・本文 | データベース（気づき） |
| 次の一歩・AI提案の日付 | データベース（その気づきの最新の完了したAI提案） |
| 本日の残り回数 | データベース（ai_usages。日本時間の日付で数える） |
| アプリ全体の上限に達したか | データベース（アプリ全体の回数） |

### AI提案のボタンと確認

| 場面 | 動き |
| --- | --- |
| 次の一歩がない | 「AI提案を受ける」を押すと、確認なしでAI提案の画面へ移り、AI提案を始める |
| 次の一歩がある | 「もう一度AI提案を受ける」を押すと、確認のシートを出す。「AI提案を受ける」でAI提案の画面へ移る |
| 本人の回数を使い切った | ボタンを押せない見た目にし、「本日のAI提案は使い切りました。明日0時に回復します。（気づきの登録は何件でもできます）」 |
| アプリ全体の上限に達した | ボタンを押せない見た目にし、「本日はAI提案の受付を終了しました。明日0時に再開します。（気づきの登録は何件でもできます）」。本人の回数ではなく、アプリ全体の都合で止まっていることがわかるようにする |
| 同じ気づきのAI提案を処理中 | 押すと「この気づきのAI提案を処理中です。しばらくお待ちください」（要件定義書 5.5 のとおり） |

**もう一度受けるときの確認（シート）**
- 「もう一度AI提案を受けますか？」
- 「新しいAI提案が完了すると、今の次の一歩は新しいものに置き換わり、元には戻せません。途中でやめた場合は、今の次の一歩が残ります。」
- 「AI提案を受ける」（塗りつぶし）、「キャンセル」、その下に「本日あと3回（受けると1回使います）」

- 押せない見た目のボタンは、押しても反応しない。画面読み上げでは「利用できません」と伝わるようにする（aria-disabled）。
- 回数を使い切ったかどうかは、画面を開いたときの値で表示し、押したときにもサーバーで必ず確かめる（画面の表示が古い場合があるため）。

### 「⋮」メニュー

- 「気づきを編集」：気づきの作成・編集画面へ移る（長い文を書くため、シートにはしない）。
- 「気づきを削除」（夕焼けの色）：確認のシートを出す。
- 本棚から削除した本の気づきも、編集・削除・AI提案ができる。

**削除の確認（シート）**
- 「この気づきを削除しますか？」
- 次の一歩があるとき：「この気づきの次の一歩（AI提案）も一緒に削除されます。削除すると、元に戻せません。」　ないとき：「削除すると、元に戻せません。」
- 「削除する」（夕焼けの色）、「キャンセル」
- 削除したら本ごとの気づき一覧へ戻り、トースト「気づきを削除しました」。

### 操作と移動先

| 操作 | 結果 |
| --- | --- |
| 戻るボタン | 前の画面へ。気づきを作成した直後は、作成画面ではなく本ごとの気づき一覧へ（履歴を置き換える。本の追加後と同じ考え方） |
| 「深掘りと回答も見る」 | そのAI提案の画面（完了したAI提案の見返し） |
| AI提案のボタン | 上の表のとおり |
| 「⋮」 | メニューのシート |

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 本の情報・気づきのカードの形のスケルトン |
| 通常 | 上の配置のとおり |
| 気づきが見つからない（削除済み・他人の気づき・存在しない ID） | 「この気づきは見つかりませんでした」と「気づき一覧へ戻る」ボタン（他人の気づきも同じ表示） |
| 読み込みの失敗 | 「気づきを読み込めませんでした。時間をおいてもう一度お試しください。」と「もう一度読み込む」ボタン |

### API（api.md で詳しく決める）

- 気づきの取得：本の情報（削除済みかを含む）、気づき、最新の完了したAI提案（日付と次の一歩）、本日の残り回数、アプリ全体の上限に達したか、同じ気づきのAI提案を処理中か、を返す。自分のものだけを返す。
- 気づきの削除：その気づきのAI提案も削除する。

## 7. 気づきの作成・編集

見本：[mockups/noteedit.html](mockups/noteedit.html)（保存したあとの画面：[mockups/aftersave.html](mockups/aftersave.html)）

気づきを新しく書く・直す画面。長い文を書くため、画面全体を使い、共通メニューは出さない（要件定義書 9章の例外）。

### 入り口

| どこから | どうすると | 見出し |
| --- | --- | --- |
| 本の詳細 | 「＋気づきを書く」 | 気づきを書く |
| 本ごとの気づき一覧 | 「＋気づきを書く」 | 気づきを書く |
| 気づきの詳細 | 「⋮」→「気づきを編集」 | 気づきを編集 |

- 本は入り口で決まっており、この画面では変えられない（要件定義書 5.3 のとおり）。
- 本棚から削除した本には、新しく気づきを書けない（入り口のボタンを出さない。サーバーでも受け付けない）。今ある気づきの編集はできる。

### 配置（上から順に）

| 部品 | 内容 |
| --- | --- |
| 見出し | 左に「×」（閉じる）、見出し、右に「保存」（灯りの色で塗りつぶし） |
| 本の情報 | 小さな表紙・タイトル・著者（変えられない） |
| 編集時の案内 | 次の一歩（AI提案）があるときだけ「編集しても、次の一歩（AI提案）はそのまま残ります。」 |
| 引用 | 「引用 任意」と「0 / 300」。紙片の見た目の入力欄。入力前の案内「心に残った一文」 |
| ページ | 「ページ 任意」。「P.」付きの数字の欄（スマホでは数字のキーボードを出す） |
| 気づき | 「気づき 必須」と「0 / 1,000」。大きな入力欄。入力前の案内「読んで考えたこと、自分の経験と結びついたことを書きましょう。」 |
| 外部AIの注意書き | 気づきの欄の下に「入力内容は、AI提案を受けるときにAI（OpenAI）に送信されます。個人情報は書かないでください。」（要件定義書 7章のとおり） |

- 「保存」を右上に置く理由：スマホでは、入力中はキーボードが画面の下半分を隠すため。
- 項目の順番を引用 → ページ → 気づきにする理由：本を読みながら一文を写し、そのあと考えたことを書く流れに合わせるため。
- 新しく書くときは、気づきの欄に自動でカーソルを入れる（必須の項目のため）。
- 文字数は、いつも「72 / 1,000」の形で表示する。数え方は要件定義書 6章のとおり（前後の空白を除き、見た目の1文字を1文字として数える）。

### 入力の確かめ方

| 場面 | 表示 |
| --- | --- |
| 入力中に文字数を超えた | 文字数を夕焼けの色・太字にする（保存を押す前から知らせる） |
| 「保存」を押した：気づきが空 | 気づきの欄の枠を夕焼けの色にし、下に「気づきを入力してください」 |
| 「保存」を押した：文字数を超えている | 「気づきは1,000文字以内で入力してください（あと24文字減らしてください）」（引用は300文字） |
| 「保存」を押した：ページが範囲外・数字以外 | 「1〜9999の数字で入力してください」 |

- 入力のエラーは、トーストで流さず、直すまで欄の下に残す（visual.md のとおり）。
- 書いている途中では「入力してください」は出さない。理由：急かされているように感じるため。
- サーバーでも同じ内容を確かめる（画面の確認は使いやすさのため、サーバーの確認は守るため）。

### 保存

- 「保存」を押すと、保存が終わるまで「保存」を押せなくする。理由：連打で同じ気づきが2件できるのを防ぐため。
- 保存したら気づきの詳細へ移り、トーストを出す。

| 場面 | トースト |
| --- | --- |
| 新しく書いた | 「気づきを保存しました」 |
| 編集した | 「気づきを変更しました」 |

- 移った先の気づきの詳細で戻るボタンを押すと、この画面ではなく本ごとの気づき一覧へ戻る（ブラウザの履歴のこの画面を、気づきの詳細で置き換える）。
- 新しく書いた直後の気づきの詳細では、本の情報の下を「今日書いた気づき」とし、「AI提案を受ける」を塗りつぶしで出す（書いた流れのまま AI 提案に進めるようにするため）。
- 保存に失敗した場合は、画面の上に「保存できませんでした。時間をおいてもう一度お試しください。」と出し、入力した内容は消さない。

### 閉じるとき

| 場面 | 動き |
| --- | --- |
| 何も書いていない（新規）・何も変えていない（編集） | 確認なしで閉じる |
| 書きかけ・変更あり | 確認のシート「書きかけの気づきを破棄しますか？」「保存していない内容は失われます。」、「書き続ける」（塗りつぶし）と「破棄して閉じる」 |
| タブやブラウザを閉じる・再読み込み | ブラウザ標準の確認を出す（beforeunload） |

- 「書き続ける」を塗りつぶしにする理由：押してほしい方を目立たせ、長い文が一瞬で消える事故を防ぐため。
- 閉じた先は、開いた元の画面（本の詳細・本ごとの気づき一覧・気づきの詳細）。
- 書きかけの内容を端末に自動で残す機能（下書き）は、MVP では作らない。

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中（編集のとき） | 入力欄の形のスケルトン |
| 本・気づきが見つからない | 「この気づきは見つかりませんでした」（新規では「この本は見つかりませんでした」）と、気づき一覧へ戻るボタン |
| 削除済みの本で新しく書こうとした（URL を直接開いた場合など） | 「この本は本棚から削除されているため、新しい気づきは書けません。」と、戻るボタン |

### API（api.md で詳しく決める）

- 気づきの作成：本の ID・引用・ページ・本文を受け取る。本が自分の本棚にあることを確かめる（削除済みの本は拒否）。
- 気づきの編集：引用・ページ・本文を受け取る（本は変えられない）。自分の気づきであることを確かめる。

## 8. AI提案

見本：[mockups/ai.html](mockups/ai.html)

深掘り（AIからの質問）→ 回答 → 次の一歩、を1つの画面で順に進める。流れ・状態・保存の決まりは要件定義書 5.5 のとおり。完了したAI提案の見返しにも使う。共通メニューは出さない（要件定義書 9章の例外）。

### 入り口

| どこから | どうすると | 表示 |
| --- | --- | --- |
| 気づきの詳細 | 「AI提案を受ける」（もう一度のときは確認のあと） | 新しいAI提案を始める |
| 気づきの詳細 | 「深掘りと回答も見る」 | 完了したAI提案を見返す |
| 再読み込み・戻る/進む・URLの直接入力 | ー | 新しいAI提案は始めない。状態に応じた表示（要件定義書 5.5「AI提案画面を開き直した場合」） |

- URL はAI提案ごとに分ける（例：`/ai/{AI提案のID}`）。新しいAI提案は、「AI提案を受ける」を押したときにサーバーで作り、その ID の URL に移る。

### 進む順番と表示

| 段階（状態） | 表示 |
| --- | --- |
| 1. 深掘りの作成中 | 「あなたの気づき」（本・ページ・引用の紙片・本文2行）。その下に芽が育つ動きと「AIが質問を考えています…」「最大1分ほどかかります」 |
| 2. 回答待ち | 「AIからの深掘り」（机の影の色・キウイ丸）、回答の入力欄（500文字まで、文字数表示）、外部AIの注意書き、「回答して次の一歩を受け取る」 |
| 3. 次の一歩の作成中 | 深掘りと「あなたの回答」を残し、芽が育つ動きと「AIが次の一歩を考えています…」「最大1分ほどかかります。この画面を離れても作成は続き、完了すると気づきの詳細に表示されます。」 |
| 4. 完了 | 深掘り・回答・「次の一歩」（番号付きのカードで1〜3個）、「気づきに戻る」（塗りつぶし）、「この次の一歩は保存されています」 |

- 外部AIの注意書き：「入力内容はAI（OpenAI）に送信されます。個人情報は書かないでください。」を回答欄のすぐ下に置く（要件定義書 7章のとおり）。
- 待っている間は、スケルトンではなく、芽がゆっくり育つ動き（2.4秒で1周）にする。理由：AIの待ち時間は中身の形がわからず、SHIORIMEらしい専用の表示にするため（visual.md「9. 操作の方針」のとおり）。「視差効果を減らす」設定の人には動かさない。
- 次の一歩の番号は、枠線と薄い灯りの色の丸で表す（押すものではないため塗りつぶさない）。
- 回答の確かめ方は、気づきの作成・編集と同じ（空のとき「回答を入力してください」、超えたとき「回答は500文字以内で入力してください（あと◯文字減らしてください）」）。
- 「回答して次の一歩を受け取る」は、押したら送信が終わるまで押せなくする（二重送信を防ぐため）。
- 「気づきに戻る」で気づきの詳細へ移る。このとき、ブラウザの履歴のこの画面を気づきの詳細で置き換え、戻るボタンで完了したAI提案の画面に戻らないようにする。

### 左上のボタンと離れるとき

| 段階 | 左上 | 押したとき |
| --- | --- | --- |
| 深掘りの作成中・回答待ち | 「×」 | 確認のシート（下）。「移動する」で気づきの詳細へ |
| 次の一歩の作成中 | 「×」 | 確認なしで気づきの詳細へ（作成は続く） |
| 完了 | 「×」 | 気づきの詳細へ |
| 見返し | 「＜」 | 気づきの詳細へ |

**回答を送る前に離れようとしたときの確認（シート）**
- 見出し「このAI提案は削除されます」
- 説明「深掘りと、入力した回答も削除されます。使った回数は戻りません。移動しますか？」（要件定義書 5.5 の確認文）
- 「回答を続ける」（塗りつぶし）、「移動する」（枠線）
- 「回答を続ける」を塗りつぶしにする理由：押してほしい方を目立たせ、回数を無駄にする事故を減らすため。
- タブやブラウザを閉じる・再読み込みでは、ブラウザ標準の確認を出す（beforeunload。表示できない場合があることは要件定義書の既知の制限のとおり）。
- シートの文字は visual.md「確認・メニューのシートの文字」のとおり。

### 失敗したとき

| 場面 | 表示 |
| --- | --- |
| 深掘りの作成に失敗 | 「AIの質問を作成できませんでした。時間をおいて、気づきの詳細からもう一度お試しください。」と「気づきに戻る」（要件定義書 5.5・6章の回数の扱いのとおり） |
| 次の一歩の作成に失敗 | 深掘りと回答を残したまま、夕焼けの枠で「次の一歩を作成できませんでした」「時間をおいて、もう一度お試しください。」、その下に「もう一度送る（回数は使いません）」 |
| 終了したAI提案を開いた | 「このAI提案は終了しました」「回答を送る前に画面を離れたため、このAI提案は削除されました。」と「気づきに戻る」 |
| 終了したAI提案に回答を送った | 「このAI提案は終了しました。気づきの詳細から新しく始めてください」（要件定義書 5.5 のとおり） |
| 次の一歩の作成中のAI提案を開き直した | 「次の一歩を作成中です。完了すると、気づきの詳細に表示されます」と「気づきに戻る」 |

### 見返し（完了したAI提案）

- 見出しは「10月20日のAI提案」、左上は「＜」。
- 上から「あなたの気づき」（AI提案を始めた時点の内容。要件定義書 5.5「気づきの内容の記録」）→ 深掘り → 回答 → 次の一歩の順に表示する。
- 「気づきに戻る」「この次の一歩は保存されています」は出さない。

### 表示する項目と出どころ

| 項目 | 出どころ |
| --- | --- |
| あなたの気づき | データベース（AI提案に記録した、始めた時点の気づきの本文・引用）と本の情報 |
| 深掘り・回答・次の一歩 | データベース（AI提案） |
| 状態 | データベース（AI提案の状態）。作成中は、画面からサーバーに一定の間隔で状態を問い合わせる（間隔は api.md で決める） |

### API（api.md で詳しく決める）

- AI提案の開始：気づきの ID を受け取り、回数を確かめて使い、AI提案を作って ID を返す。
- AI提案の取得：状態と、深掘り・回答・次の一歩、記録した気づきを返す。自分のものだけ。
- 回答の送信、次の一歩の作成の再送（回数は使わない）、開き直したときの終了の通知。
- 作成中の状態をどう画面に伝えるか（問い合わせの間隔、待ち時間の上限）は api.md で決める。
