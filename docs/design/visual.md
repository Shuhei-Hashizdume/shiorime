## 1. 世界観

- テーマは「夜の読書灯」。深い青緑の部屋に、電球色の灯りがともる。
- 落ち着き・癒やしを感じる、静かな雰囲気にする。
- 理由：ターゲットは、仕事を終えた夜に本を読む社会人であり、寝る前に開いても目が疲れず、心が落ち着く画面にするため。
- 明るい表示（ライトモード）のテーマは「朝日の差す机」。朝活で本を読む時間に、窓から朝日が差しこむ机をイメージする。
- 理由：社会人が本を読むのは、仕事終わりの夜と、早起きした朝の2つの時間帯が多いため。夜は落ち着き、朝はさわやかさを表す。

## 2. 名前とキャッチコピー

### アプリ名

- 表記：SHIORIME（よみ：しおりめ）
- 意味：栞（しおり）＋芽（め）の造語。栞を挟んだところ（読書で得た気づき）から新しい芽が出て、行動へと育っていく。読書と成長の両方を表す。
- 栞の語源：「枝折（しおり）」とも書き、山道で木の枝を折って道しるべにしたことが由来とされる。栞（枝を折って進む道の目印）と芽（枝の先に出る成長の始まり）は、どちらも植物につながり、「目印」から「成長」への流れになる。

### キャッチコピー

- 「今夜の栞を、明日の芽に。」

| 言葉 | 意味 |
| --- | --- |
| 今夜の栞 | 夜の読書で、心に残ったところに挟んだ目印（＝気づき） |
| 明日の芽に | その目印を、明日の成長の始まりにする |

## 3. 色

| 名前 | 値 | 使う場所 |
| --- | --- | --- |
| 夜の部屋 | `#14232B` | 画面の背景 |
| 机 | `#1C3039` | 気づきなどのカードの背景 |
| 机の影 | `#233B45` | AIからの深掘りのカード、区切り |
| 夜の床 | `#101C22` | 画面下部の共通メニューの背景 |
| 紙の白 | `#ECE6D8` | 主な文字 |
| やわらかい文字 | `#D5CFC2` | 気づきの本文など、長い文章 |
| 控えめな文字 | `#9AA7AC` | 補足（著者・ページ番号・日付など） |
| 読書灯 | `#E2A84B` | 主なボタン、選択中のメニュー、栞、ロゴの芽 |
| 灯りに照らされた紙 | `#F1D9A8` | 引用符のアイコン |
| 引用の紙 | `#24363A` | 引用（本の言葉）の紙片の背景 |
| 夕焼け | `#EE9A8F` | エラー（入力の誤り・AIの失敗）、削除ボタン |
| 若葉 | `#8FC1A0` | 成功（保存・追加・変更の完了を伝えるトースト） |

- 主なボタンは「読書灯」の背景に「夜の部屋」の文字とする。
- 灯りの色で塗りつぶすのは「押すボタン」だけとする。画面の上の切り替え（例：本棚の「読書中・読了・すべて」）の選択中は、灯りの色の枠線と文字に、薄い灯りの色の背景（夜は `rgba(226,168,75,.16)`、朝は `rgba(232,162,58,.18)`）で表す。朝の枠線と文字は「朝日に照らされた紙」を使う。理由：同じ塗りつぶしが2つ並ぶと、どれを押せばよいかがわかりにくくなるため。
- 削除ボタンは「夕焼け」の背景に「夜の部屋」の文字とし、取り消せない操作の確認でだけ使う。
- 「注意（警告）」の色は作らない。理由：黄色・オレンジは「読書灯」と重なって紛らわしくなるため。注意を伝える場面は、確認のシートで対応する。
- エラー・成功は、色だけで伝えない。エラーには直し方がわかる文章と記号を、成功のトーストにはチェックの記号を必ず添える。理由：色の見分けが苦手な人にも伝わるようにするため。
- エラーはトーストで流さず、直すまでその場に残して表示する。
- 見やすさ：「夕焼け」「若葉」は、「夜の部屋」「机」「机の影」のどの背景の上でも、文字と背景の明るさの差が 4.5 以上あり、ウェブの見やすさの基準（WCAG）を満たす。
- エラー・成功の表示の見本は [mockups/states.html](mockups/states.html) を参照。
- 理由：深い青緑と電球色の組み合わせで、夜の読書灯の世界観を表すため。アクセント色を「読書灯」の1色に絞り、画面を落ち着かせるため。

### 明るい表示（朝日の差す机）

| 名前 | 値 | 使う場所（夜の表示で対応する色） |
| --- | --- | --- |
| 朝の部屋 | `#FBF7EC` | 画面の背景（夜の部屋） |
| 朝の机 | `#FFFFFF` | カードの背景、共通メニューの背景（机・夜の床） |
| 朝の机の影 | `#F3EBD6` | AIからの深掘りのカード、区切り、共通メニューの上の線（机の影） |
| 墨 | `#2B3238` | 主な文字、主なボタンの文字（紙の白） |
| うすい墨 | `#454D54` | 気づきの本文など、長い文章（やわらかい文字） |
| 控えめな墨 | `#62686E` | 補足（著者・ページ番号・日付など）（控えめな文字） |
| 朝日 | `#E8A23A` | 主なボタンの背景、栞、ロゴの芽（読書灯） |
| 朝日に照らされた紙 | `#8A5A12` | 引用符のアイコン、選択中のメニュー（灯りに照らされた紙） |
| 朝の引用の紙 | `#FBF3E1` | 引用（本の言葉）の紙片の背景（引用の紙） |
| 朝焼け | `#AE4035` | エラー、削除ボタン（夕焼け） |
| 朝の若葉 | `#2A7350` | 成功（若葉） |

- 主なボタンは「朝日」の背景に「墨」の文字とする（明るさの差 5.98）。
- 削除ボタンは「朝焼け」の背景に白（`#FFFFFF`）の文字とする（明るさの差 5.86）。
- 「朝日」は文字の色には使わない。理由：明るい背景との明るさの差が約 2.0 しかなく、読みにくいため。選択中のメニューの文字・アイコンは「朝日に照らされた紙」を使う。
- 見やすさ：文字に使う色は、「朝の部屋」「朝の机」「朝の机の影」のどの背景の上でも、明るさの差が 4.5 以上ある（最も低いのは「控えめな墨」と「朝の机の影」の 4.74）。
- ロゴの本のページは、明るい表示では「墨」で描く（芽と灯りは同じ色のまま）。
- 理由：夜と朝でアクセント色（灯り・朝日）をほぼ同じ色にし、どちらの表示でも同じアプリだとわかるようにするため。
- 注意：クリーム系の背景は、AI が作るサイトでよく使われる色に近い。「朝日の差す机」の色に加えて、独自のアイコン・栞・2つの丸い書体を組み合わせることで、ありがちな見た目にならないようにする。
- 見本は [mockups/morning.html](mockups/morning.html) を参照（4つの画面のうち、一番右が採用した案）。

### 夜と朝の切り替え

- 初めは、端末の設定（ダークモード／ライトモード）に合わせる。
- プロフィールの画面で「端末の設定に合わせる／夜（暗い表示）／朝（明るい表示）」から選べる。
- 選んだ表示は端末のブラウザに保存する（サーバーには保存しない）。理由：見た目だけの設定のため、データベースや API を増やさずに済む。端末ごとに変えたい人にも合う。
- 画面を開いた瞬間に、違う表示が一瞬見える（ちらつく）ことがないよう、ページの読み込みの最初に表示を決める。

## 4. 書体

| 書体 | 使う場所 |
| --- | --- |
| キウイ丸（Kiwi Maru） | 本の言葉（引用）、AIからの深掘り、キャッチコピー、ロゴのよみがな |
| Zen 丸ゴシック（Zen Maru Gothic） | 操作・本文・見出し、ロゴの「SHIORIME」 |

- 読み込めない場合の代わり：ヒラギノ丸ゴシック。
- 理由：角が丸く、やさしい印象の書体にするため（明朝体は硬い印象になるため使わない）。本の言葉とAIの言葉には、筆の流れを残したキウイ丸を使い、操作の文字と区別するため。

### 文字の大きさの段階（スマートフォン基準）

| 段階 | 大きさ | 使う場所 |
| --- | --- | --- |
| 大見出し | 24px | ウェルカムページのキャッチコピー、画面のタイトル |
| 見出し | 20px | 本のタイトル（本の詳細）など |
| 小見出し | 17px | カードの見出し、AIからの深掘り |
| 本文 | 16px | 気づきの本文、入力欄、ボタン |
| 補足 | 13px | 著者・ページ番号・日付 |
| 最小 | 12px | 共通メニューの文字 |

- 行の高さ：本文は1.8倍、見出しは1.4倍。
- 理由：
  - 本文を16pxにするのは、気づきは最大1000字と長く、暗い背景では文字が細く見えるため、小さすぎない大きさにするため。また、Apple・Google とも本文は16px前後を勧めているため。
  - 入力欄を16px以上にするのは、iPhone の Safari では16pxより小さい入力欄に入力しようとすると、画面が自動で拡大されてしまうため。
  - 本文の行の高さを1.8倍にするのは、日本語の長い文章を読みやすくするため。
  - 段階を6つに絞るのは、新しい画面を作るときに迷わないようにするため。

## 4-2. 余白・角丸・影

### 余白

8の倍数を基本にした、次の段階だけを使う。

| 段階 | 大きさ | 使う場所の例 |
| --- | --- | --- |
| 極小 | 4px | 文字とアイコンの間 |
| 小 | 8px | カードの中の項目どうしの間 |
| 中 | 16px | 画面の左右の余白、カードの内側の余白 |
| 大 | 24px | カードとカードの間、まとまりの区切り |
| 特大 | 40px | 画面の一番上、大きな区切り |

- 理由：余白の段階をそろえることで画面が整い、どこを読めばよいか迷いにくくするため。使ってよい数値を決めておくことで、AIに実装させても画面ごとに余白がばらつかないようにするため。

### 角丸

大きさに応じて変える（すべてを同じ角丸にしない）。

| 対象 | 角丸 | 理由 |
| --- | --- | --- |
| カード（気づき・AI提案など） | 16px | やわらかい印象にするため |
| 入力欄・小さな部品 | 12px | カードより一段小さくし、入れ子に見えるようにするため |
| ボタン | 完全な丸（両端が半円） | 押せる部品だと一目でわかるようにするため |
| 下から出るシート | 上の角だけ 20px | 画面の下からせり上がる形を表すため |
| アプリのアイコン | 22% | ホーム画面のほかのアプリのアイコンとなじませるため |

### 影

- 影は使わない。重なりは、背景の色の明るさの差（夜の部屋 → 机 → 机の影）で表す。
- 理由：暗い背景では影がほとんど見えず、色の明るさの差のほうが夜の部屋の落ち着いた雰囲気に合うため。また「どこも同じ角丸＋薄い影」はAIが作ったように見える定番の表現であり、これを避けるため。

## 5. ロゴとアイコン

### アイコン

- 「読書灯に照らされた芽」：開いた本のまん中から芽が伸び、その後ろに読書灯の灯りがある。
- 描き方は影絵（塗りつぶし）。本は「紙の白」、芽と灯りは「読書灯」。
- 形の正確な定義は [mockups/logo.html](mockups/logo.html) の SVG を正とする。

### ロゴ（アイコン＋名前）

基本的に「SHIORIME＋アイコン」の組み合わせで表示する。

| 並べ方 | 形 | 使う場所 |
| --- | --- | --- |
| 横並び | 背景のないアイコン＋「SHIORIME」 | 各画面の左上（ヘッダー） |
| 横並び（背景あり） | 角丸の四角に入ったアイコン＋「SHIORIME」 | README、ブラウザのタブ、ホーム画面のアイコン |
| 縦並び | アイコン＋「SHIORIME」＋「しおりめ」 | ウェルカムページ |

- 「SHIORIME」は Zen 丸ゴシックの太字で、文字の間隔を少し広めに空ける。

### 画面内で使うアイコン

| 種類 | 例 | 方法 |
| --- | --- | --- |
| 決まった記号 | 戻る、閉じる、⋮、検索、＋（追加）、チェック | Phosphor Icons（MITライセンス）を使う。導入時に最新のライセンス表記を確認する |
| アプリの顔になるもの | 共通メニューの「本棚」「気づき」「プロフィール」 | 独自に描く。形は [mockups/tabicons.html](mockups/tabicons.html) の SVG を正とする |

- 共通メニューのアイコンは、選択中は塗りつぶし＋「読書灯」の色＋文字を太字、選択していないときは線＋「控えめな文字」の色で表す。
- 「気づき」のアイコンは、栞を挟んだページの形にし、気づきのカードの栞とつなげる。
- 理由：戻る・閉じるなどの記号は、Apple・Google の手引き書が勧めるとおり、誰もが知っている形を使って迷わないようにするため。アプリの顔になるアイコンは、アプリのアイコンと同じやわらかい形でそろえ、SHIORIMEらしさを出すため。選択中かどうかを色だけでなく形でも表し、色の見え方に左右されないようにするため。Lucide は使わない（「10. 避けるもの」のとおり）。

## 6. 栞と引用の表現

### 栞

- 気づきのカードの右上に、「読書灯」の色の栞を付ける。アプリ全体の目印として使う。
- 画面を開いたときに、栞が上から1回だけ下りてくる動きを付ける（約0.5秒）。
- 端末の「視差効果を減らす」設定がオンの人には、動かさずに表示する。

### 引用（本の言葉）

- 引用は「紙片」で表す：本から切り取った紙を貼ったように、引用だけを色の違う紙の上に置き、左上に引用符のアイコンを添える。書体は「キウイ丸」、文字の色は主な文字の色（夜は「紙の白」、朝は「墨」）。「」では囲まない。
- 紙片の色：夜は「引用の紙」`#24363A`、朝は「朝の引用の紙」`#FBF3E1`。角丸は10px、内側の余白は上下10px・左右12px（アイコンの分、左は34px）。
- 引用符のアイコンは独自に描き、夜は「灯りに照らされた紙」、朝は「朝日に照らされた紙」の色にする。
- 紙片は「机」（カード）の上に置く前提の色とする。「机の影」（AIからの深掘りのカードなど）の上に引用を置く場合は、紙片の色が背景と近くなるため、その画面を設計するときに見え方を確認する。
- 理由：本の言葉と、利用者自身の言葉（気づきの本文）を一目で区別できるようにするため。色を変えるだけでは見た目が弱く、区切りが一番はっきりする紙片を選んだ（比べた5案は mockups/quote.html）。
- 以前の見本（welcome.html・morning.html・states.html）は、色を変えるだけの古い引用の表現のまま残っている。実装ではこの決まりに従う。

## 8. 使いやすさの決まり

Apple の「ヒューマンインターフェイスガイドライン」と Google の「マテリアルデザイン3」を、使いやすさの決まりとして取り入れる。見た目（色・書体・アイコン）はこの文書の独自のものとする。

- 指で押すもの（ボタン・メニューなど）は、最低でも44〜48ピクセル四方にする。
- よく使う画面（本棚・気づき一覧・プロフィール）は、画面下の共通メニューで移動する。
- 確認や短い操作は、下から出るシート（モーダル）で行う。
- 文字の大きさの段階（「4. 書体」のとおり）を、全画面で統一する。
- 文字と背景の明るさに十分な差をつける。
- 操作の結果は、すぐに利用者に伝える。
- 削除のような取り消せない操作では、必ず確認を出す。

## 9. 操作の方針

操作は、ストレスなく使えることを最優先にする。次の手法を、使う場所を決めて使う。

| 手法 | 使う場所 | 注意点 |
| --- | --- | --- |
| モーダル（スマホでは下から出るシート） | 確認（削除・退会・AI提案を離れるとき）、短い入力（本のタイトル・著者の編集）、「⋮」メニュー、利用規約・プライバシーポリシー | 長い入力（気づきの作成）には使わない |
| トースト | 保存・削除・変更が終わったとき | エラーはトーストで流さず、その場に残して表示する |
| スケルトンスクリーン | 本棚、気づき一覧、本ごとの気づき一覧、本の検索結果 | AIの処理中は使わない（専用の処理中表示にする） |
| アニメーション | 画面の切り替え、モーダルの開閉、AIの処理中、次の一歩の表示、栞 | 短く控えめにする。「視差効果を減らす」設定の人には動きを止める |
| アコーディオン | AI提案の履歴 | 本ごとの気づき一覧には使わない |
| スワイプ操作 | スマホでの、一覧の項目の削除・編集の近道 | 「⋮」メニューを必ず残す。スワイプでも削除前に確認を出す |
| 下に引っぱって更新 | 使わない | 更新する場面がほとんどなく、ブラウザの同じ動きとぶつかるため |

- 編集・削除は、ボタンを並べず、タイトル右上の「⋮」メニューから操作する（アプリ全体で統一する）。

## 10. 避けるもの

AIが作ったように見える画面を避けるため、次のものは使わない。

- 絵文字
- 左側にだけ線を付けて強調する表現
- Lucide アイコン
- 紫〜青のグラデーション、ガラスのような半透明の効果、キラキラの飾り
- どこも同じ角丸のカードと薄い影を並べただけの画面
- 特徴を3つのカードで横に並べる構成
- 標準の書体をそのまま使うこと
- Apple の SF Symbols・SF フォント（Web アプリでは利用できないため）

## 11. 動きの長さ

| 長さ | 使う場面 | 理由 |
| --- | --- | --- |
| 100ms | ボタンを押したときの反応（少し縮んで暗くなる） | 人は0.1秒以内の反応を「すぐ反応した」と感じ、それより遅いと押せたか不安になるため |
| 200ms | トーストの表示、アコーディオンの開閉 | 画面の一部が変わるだけで、何度も使う操作のため、待たせない |
| 300ms | シート・モーダルの出入り | 画面の大部分が動くため、どこから出てきたかを目で追える長さにする（Material Design 3 の目安 250〜400ms の範囲） |
| 2秒／2.5秒 | トーストを表示しておく時間。15文字までの短い文は2秒、それより長い文は2.5秒 | 実際に表示して確かめ、短い文は2秒で読み切れ、3秒では長く感じたため。長い文（例：「読了にしました（本棚の「読了」に移りました）」）は、読み切れるよう少し長くする。結果は画面の内容でも確かめられるため、見逃しても困らない |
| 1.6秒で1周 | スケルトンの明滅 | ゆっくり明滅させ、急がされている感じを出さないため |
| 約0.5秒（例外） | ウェルカムページで栞が下りる動き | 1回だけの演出のため |

- 実装では、100ms・200ms・300ms の3つを CSS の変数にして使う。ほかの長さを新しく作らない。
- 出てくるときは、だんだん遅くなる動き（ease-out）にする。消えるときは、だんだん速くなる動き（ease-in）にし、出るときより短くする（例：トーストは200msで出て150msで消える）。理由：終わり際にゆっくり止まると、自然に「置かれた」ように見えるため。
- トーストに出すのは成功の知らせだけとし、表示時間は文の長さで2秒（15文字まで）と2.5秒（16文字以上）の2段階にする。文字数は「（」「」」などの記号も含めて数える。トーストに操作（「元に戻す」など）は置かない。
- トーストの文はできるだけ15文字以内に収める。長い文が増えると、表示が長いトーストが増えるため。
- 体感の見本は [mockups/toast.html](mockups/toast.html) を参照。
- シート・モーダルを開いている間は、後ろの画面を固定し、スクロールもさせない。シートだけが下から出てくる。後ろの画面は位置を変えずに薄く暗くする。
- 端末の「視差効果を減らす」設定がオンの人には、移動する動きをやめ、その場で切り替えるか、薄く現れる動きだけにする。スケルトンの明滅も止める。
- 見本は [mockups/motion.html](mockups/motion.html) を参照。

## 12. フォーカス（キーボードで操作したときの表示）

- キーボードで操作したときだけ表示する（CSS の `:focus-visible`）。タップ・クリックでは表示しない。理由：タップで枠が出ると、不具合のように見えるため。
- 形は、2pxの線を、部品から3px離して囲む。部品の角丸に合わせる。理由：主なボタン自体が灯りの色のため、間をあけないと枠とボタンが一体化して見えないため。
- 色は、夜は「読書灯」（`#E2A84B`）、朝は「朝日に照らされた紙」（`#8A5A12`）。どの背景の上でも明るさの差が 4.97 以上あり、WCAG の基準（3 以上）を満たす。朝の「朝日」は明るさの差が約 2.0 のため使わない。
- シート・モーダルを開いたら、フォーカスをシートの中に移す。閉じたら、開いたボタンに戻す。Esc キーで閉じられるようにする。
- フォーカスを移すときは、画面を動かさない指定（`focus({ preventScroll: true })`）を付ける。理由：付けないと、ブラウザがフォーカスした部品を見せようとして、後ろの画面ごと動いてしまうため。
- フォーカスが移る順番は、画面の見た目の順番（上から下、左から右）と揃える。
